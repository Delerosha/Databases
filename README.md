# Домашнее задание к занятию "`«Базы данных, их типы»`" - `Мальцев Андрей`

### Задание 1. СУБД

**Кейс.** Крупная строительная компания, которая также занимается проектированием и девелопментом, решила создать правильную архитектуру для работы с данными. Ниже представлены задачи, которые необходимо решить для каждой предметной области. Какие типы СУБД, на ваш взгляд, лучше всего подойдут для решения этих задач и почему?

**1.1.** Бюджетирование проектов с дальнейшим формированием финансовых аналитических отчётов и прогнозирования рисков. СУБД должна гарантировать целостность и чёткую структуру данных.

**Ответ:** Рекомендуемый тип СУБД: **реляционная** (PostgreSQL или MySQL). Их плюсы — целостность и структурированность.

**1.2.** Под каждый девелоперский проект создаётся отдельный лендинг, и все данные по лидам стекаются в CRM к маркетологам и менеджерам по продажам. Какой тип СУБД лучше использовать для лендингов и для CRM? СУБД должны быть гибкими и быстрыми.

**Ответ:** Рекомендуемый тип СУБД для лендингов и CRM: **документоориентированная (NoSQL)** — MongoDB или Couchbase. Их плюс — гибкость и быстродействие.

**1.3.** Отдел контроля качества решил создать базу по корпоративным нормам и правилам, обучающему материалу и так далее, сформированную согласно структуре компании. СУБД должна иметь простую и понятную структуру.

**Ответ:** Рекомендуемый тип СУБД: реляционная (лёгкая, например SQLite для небольшого объёма или PostgreSQL для масштаба).

**1.4.** Департамент логистики нуждается в решении задач по быстрому формированию маршрутов доставки материалов по объектам и распределению курьеров по маршрутам с доставкой документов. СУБД должна уметь быстро работать со связями.

> **Ответ:** Рекомендуемый тип: **реляционные СУБД**. Они помогут эффективно работать со связями между объектами, такими как курьеры и маршруты. Легко моделировать и настраивать динамические изменения, быстрая работа со связями.

### Задание 2. Транзакции

**2.1.** Пользователь пополняет баланс счёта телефона. Распишите пошагово, какие действия должны произойти для того, чтобы транзакция завершилась успешно. Ориентируйтесь на шесть действий.

**Ответ:**

1. **Инициирование запроса** — пользователь вводит данные (номер телефона, сумму).
2. **Валидация и аутентификация** — платёжный шлюз проверяет корректность номера, достаточность средств; если всё ок — транзакция переходит в статус «подтверждена».
3. **Списание средств с источника и зачисление на транзитный счёт** — деньги списываются со счёта пользователя и поступают на транзитный счёт платёжного агрегатора.
4. **Проведение взаиморасчётов между агрегатором и оператором** — платёжный агрегатор отправляет уведомление оператору связи о зачислении денег (обычно через API).
5. **Зачисление средств на баланс абонента** — оператор связи увеличивает баланс лицевого счёта (или предоплаченного баланса) на сумму пополнения.
6. **Подтверждение и завершение** — оператор возвращает агрегатору успешный ответ, агрегатор — платёжному шлюзу, шлюз — пользователю (чек, push-уведомление).

**2.1.\*** Какие действия должны произойти, если пополнение счёта телефона происходило бы через автоплатёж?

**Ответ:**

1. **Срабатывание триггера автоплатежа** (например, после оказания услуги связи баланс стал < 30 руб.).
2. **Проверка мандата и резервирование средств** — платёжный шлюз по сохранённому токену запрашивает резервирование суммы (фиксированной или динамической).
3. **Автоматическое списание** — без участия пользователя списываются средства.
4. **Зачисление на транзитный счёт и уведомление оператора** — аналогично шагам 3–4 ручного пополнения.
5. **Зачисление на баланс абонента** — аналогично шагу 5 ручного пополнения.
6. **Уведомление абонента** (push или смс).

**Отличия от ручного пополнения:**
- Нет шага «инициирование пользователем».
- Предварительное согласие (мандат) — пользователь один раз подписывает соглашение (как подписка на Кинопоиск).
- Автоматическая проверка лимитов — шаг валидации проходит без участия пользователя.
- Логирование причины запуска — в транзакции фиксируется триггер (например, баланс или дата для продления подписки).

### Задание 3. SQL vs NoSQL

**3.1.** Напишите пять преимуществ SQL-систем по отношению к NoSQL.

**Ответ:**

1. **Строгая согласованность и ACID-транзакции** — SQL-базы данных обеспечивают атомарность, консистентность, изоляцию и долговечность транзакций. Это гарантирует, что даже при сбоях или одновременных операциях данные останутся целостными.
2. **Жёсткая структура данных и контроль целостности** — данные организованы в таблицы с заранее определёнными схемами, типами данных, первичными и внешними ключами. Это обеспечивает строгий контроль целостности.
3. **Стандартизация** — SQL является стандартом в мире баз данных, что делает его универсальным и широко применяемым языком.
4. **Безопасность** — SQL-базы данных предоставляют хороший контроль: можно назначать права на уровне пользователей, ролей, таблиц, столбцов или даже строк. Поддерживаются аутентификация, шифрование данных, аудит действий.
5. **Мощный язык запросов** — SQL позволяет выполнять сложные запросы с объединениями, подзапросами, оконными функциями и агрегациями.

### Задание 4. Кластеры

Необходимо производить большое количество вычислений при работе с огромным количеством данных, под эту задачу выделено 1000 машин. На основе какого критерия будете выбирать тип СУБД и какая модель распределённых вычислений здесь справится лучше всего и почему?

**Ответ:**  
**MapReduce и Apache Spark** (модель DAG с in-memory вычислениями).  
Они позволяют разбить задачу на тысячи независимых частей, обрабатывать их параллельно на каждой машине, а потом собрать результат. Система сама балансирует нагрузку и переживает отказы отдельных машин. 
Spark поддерживает SQL, датафреймы, машинное обучение и графы «из коробки».
